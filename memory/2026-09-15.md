## Key Decision: Svelte Lines Table Integration Pattern
Adopted a hybrid approach where the classic Scheduler (`window.Scheduler`) remains the single source of truth for state, while a Svelte 4 virtual-scrolling table renders the UI. The Svelte component is loaded dynamically and guarded by a feature flag `S.__USE_SVELTE_LINES`.

- **Default**: Classic `renderLines()` runs (backward compatible)
- **Svelte mode**: Enable via `?lines=svelte` URL param or `localStorage.setItem('blade:lines:svelte', '1')`
- **Integration**: Svelte component pulls data via `S.getLineRowModels()` — a new read-only method that transforms `S.state.lines` into the export-shaped row model format
- **Mutation flow**: Svelte dispatches CustomEvents (`lines:day-toggle`, `lines:inline-edit`) which classic handlers process, then call `S.renderLines()` which is a no-op in Svelte mode, instead re-fetching via `getLineRowModels()`
